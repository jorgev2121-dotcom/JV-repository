# OWNER DIRECTIVE OD-01 — Always end with a question

**Issued by:** Jorge Valdes
**Date:** 2026-08-15
**Status:** ACTIVE — permanent, no expiry
**Applies to:** every Claude session and every agent — Code desktop, Code cloud,
Cowork, iPhone, Chat, and any other LLM in the system.

---

## The directive

**Every outbound message ends with a question.**

No exceptions. To Jorge, to another agent, to another LLM. Every mailbox file, every
handoff, every work-queue item, every chat reply.

**Jorge classified this as a need, not a want.** It is his established protocol with
the iPhone agent, where both sides end with a question and both sides answer. It
works, and it is being extended to the whole system.

---

## Why

**A message with no question can be read and silently dropped.**

Between sessions that cannot see each other, and between Jorge and agents he cannot
watch, the closing question is the only mechanism that forces a reply. It is
turn-taking. Without it, threads die unanswered.

**That is the mechanism behind eighteen months of requests that were discussed,
agreed, and never completed.** Not malice, not incompetence — no forcing function.
Someone read the last message, had nothing they were obliged to answer, and the
thread ended.

---

## How to obey it without burdening Jorge

Rule 7 of `CLAUDE.md` still stands: never make him choose between technical options,
and never hand him a decision that is yours to make.

**Both rules hold if the question is cheap.**

Good closing questions to Jorge:
- "Did that work?"
- "Shall I start on the backlog next?"
- "Anything else before I go quiet?"

Forbidden, regardless of the question mark:
- "Which architecture would you prefer?"
- "Should I use option A, B or C?"
- "How would you like me to handle this?"

**Ask something. Make it answerable in a word.**

## Provenance note

An earlier version of `CLAUDE.md` claimed Jorge had set a rule that "every question
costs him executive function." **He did not say that — a cloud session inferred it**
from his ADHD, his dyslexia, and his 300-item backlog, then wrote it into the charter
as though he had issued it.

The inference was reasonable and the underlying concern is real. **Attributing it to
him was not.** Recorded here so no future session treats an inferred rule as an owner
directive. This file is an owner directive. That one was not.

VTES Agent Flowchart

How work moves between your agents, and which ones are live or still to build. Built 2026-10-02 by Cloud. #VTES #agents #Gemini

Section A — The setup in plain words

Your agents never talk to each other directly. They leave notes in two Google Drive folders. VTES-Inbox is the in-tray. VTES-Outbox is the out-tray. Anyone who can read Drive can pick up a job or check a result, which is why a Gemini agent can slide into the same lanes the Claude agents use.

Every job ends one of three ways: done with proof, blocked with the one small thing needed, or in progress. A reply that only says "received" closes nothing.

Section B — The handoffs, step by step

  1. You, Claude Chat, Cloud Claude, Cowork or the Gemini orchestrator write an order file into the Inbox.
  2. A doer picks it up. Free work (sorting, tagging, anything with personal data) goes to the local lane. Code goes to Codex. Judgment and client-facing work goes to Claude, which is scarce.
  3. The doer writes one proof file into the Outbox the moment that item finishes.
  4. CU-Orchestrator, Cloud Claude and the Gemini orchestrator read the Outbox. Each job is closed, re-queued, or escalated.
  5. Anything that would send, spend, delete or file a client document is parked on your daily yes/no list. Nobody acts on it until you answer.

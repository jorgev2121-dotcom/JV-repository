Every older scenario of test-verify.sh whose expectation changed, and why. Nothing was weakened silently: each change is a CONSEQUENCE of the new strict rule
"a fresh install is EXACT; a changed data or settings file is allowed only with -AfterWriters and only if it passes the strict shape check". Every other old scenario
(V01-V03, V05, V07-V13, V15-V35, V38, V40-V45, V30) keeps its old expected answer unchanged and passes.

Also changed for ALL scenarios (stronger, not weaker): every scenario now runs under `timeout 60`, takes a before/after snapshot that also records type, mode, size, mtime and link
target of every entry (the old snapshot recorded type, mode and size), asserts it finished in under 58 seconds, and is counted as a scenario. "11 of 11" is no longer hard-coded:
the file count is read from the package manifest.

   Why: day one is exact (the manifest hash is exact). The old "expected edit" came from an allowance with no check behind it (CHECK-8 flaw 4).

   -AfterWriters: exit 0), V04e (the same properly shaped file WITHOUT the switch: PROBLEMS).

   OLD expectation: exit 0, "EDITED (data file) - expected: data/vtes5-bots.js".

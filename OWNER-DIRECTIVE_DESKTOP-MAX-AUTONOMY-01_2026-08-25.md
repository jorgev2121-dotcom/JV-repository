## The rule
**The desktop proceeds autonomously on ANY reversible / GREEN task without pinging Jorge.**
It does the work, writes evidence to a file, and reports — it does NOT wait for permission on
anything it can safely undo.

## GREEN — do it, don't ask (proceed autonomously)
Research · reading · OCR · drafting (emails, letters, scripts — held as drafts, not sent) ·
reconciling · enumerating/counting · staging files for a later move · fixing/backing-up configs
(e.g. wiring an existing key, locking a service to localhost) · building lists · anything that
writes only to a NEW file or is backed-up + reversible.

## RED — still parks for Jorge (this is a SAFETY line, not "owner participation")
Kept because a misfire here is found by a **client months later**, not by us:
1. **Anything OUTBOUND** — sending an invoice, proposal, email, or any money.
2. **Moving / renaming / deleting a client document** — one digit misfiles it (the `14598 SW 110 ST`
   near-miss). Nights prepare filing; a human executes it.
3. **New spend, new credentials, new signups.**
4. **Security posture changes that WIDEN exposure** (opening a port, disabling protection).
   *(Narrowing exposure — e.g. 0.0.0.0 → 127.0.0.1 — is GREEN.)*

## Still bounded by the FREEZE
No NEW systems/agents/protocols get BUILT (Article 1). Autonomy applies to **finishing existing
work** and the three sanctioned workstreams (Wally · cash collection · JOB-0079 pilot).

## Cloud's role unchanged
Cloud remains the QC / pushback layer and carries the repo. The desktop's autonomy does not remove
QC — cloud verifies batches; the desktop still writes each result to disk as it completes.

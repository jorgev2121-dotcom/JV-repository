## Section D — The job capsule (every folder under 01-JOBS)

**Folder name:** `TRK-2026-NNNN _ Address short _ Party` (TRK first so it sorts; no parentheses; no `TRK-TBD`). Address short and Party are the building address without city and the client surname, each at most 30 characters.

**`00-INDEX.md` has two parts.** (1) **Human part**, written by a person or an agent: identity, **ALIASES (every other number or folder name for this job)**, parties, status, next action, `where:` lines. (2) **Generated part**, rebuilt by script and never hand-edited: file list, counts, and the "counted on" date. The generated list **excludes `.bak` and sidecars.**

**Menu of sub-folders, created only when the first file needs one:** `01-INTAKE-ORIGINALS`, `02-GOVERNMENT`, `03-CLIENT` (one sub-folder per party), `04-WORKING-PAPERS` (every conclusion must trace to a file here), `05-REPORTS-DELIVERED` (what was sent, when, to whom), `06-FINANCIAL`, `07-TAX-JACKET` (kept as is), `08-CORRESPONDENCE`, `_Superseded`. An empty folder is a defect: the sweeps found five empty Bay Harbor shells and four empty 20001 folders.

## Section E — Naming

**Identity grammar.** `TRK-2026-NNNN`, then an optional **`-SUFFIX`** (unit or party, upper-case letters and digits, for example `-U221`, `-PZ305`, `-JULIA`), then an optional **`.NNNN` subordinate document number** (the dot means "document number in this job", never a page).
- **Existing `.NNN` and dash forms are conforming and must never be renamed.** Renaming `1442.001` to bare `1442` would make 20 documents collide.
- A validator reads the base `TRK-2026-NNNN` first and treats the suffix as a child of it. The suffix meaning (unit, party, document type) is recorded in the job's `ALIASES` line.
- **Forbidden:** `.NNN` used as a **page** number, the short form `TRK-26-`, parentheses around a TRK, `Copy`, `(2)`, `FINAL`, `final2`.
- **Exempt from the job grammar, with fixed names:** `README-FIRST.md`, `FILING-CONSTITUTION.md`, `AGENT-INDEX.md`, `00-INDEX.md`, `CONTESTED-IDS.md`, `TREE-COUNTS.md`, portal and log files. **Orphans** are named `YYYY-MM-DD _ OPH-2026-NNNN _ TYPE _ Description _ v1.ext`.

**File name:** `YYYY-MM-DD _ TRK-2026-NNNN _ TYPE _ Description _ vN.ext`, optional `_ pNNN` last.
- **TYPE is a closed list:** Permit, Report, WorkingPaper, Invoice, Contract, Correspondence, Photo, Scan, Form, Notice, Receipt, Plan, Survey, Title, Note, TaxJacket, DDBook, DDResearch, Index, Log. A new type needs an amendment.
- **Version is a bare `vN`.** "CORRECTED" becomes the next number.
- **Date:** the document's own date; for an invoice, the issue date; with none, the filing date.
- **Length limits:** file name at most 120 characters, full path at most 220 (Windows fails silently near 260).
- **Hashtags** go in the body or metadata, never the filename.
- **Status is separate from version** and lives in `00-INDEX.md`: DRAFT, SENT, EXECUTED, VOID, INVALID.

## Section F — Intake, OCR and "email circles"

**Four doors into `02-INTAKE`:** `SCANS`, `EMAIL-CIRCLES`, `DOWNLOADS`, `IPHONE`. **Every item gets an `OPH-2026-NNNN` at the door**, as `ORPHAN-NUMBERING.md` says. The intake agent then tries to resolve it under Rule 5.

For each item, in order:
1. **OCR it without touching the original.** The text layer and stamp go in a **`.SEARCH.txt` sidecar whose FIRST line is** `TRK | hashtags | address | folio | doc type | date`, then the text. (Audit: only about 6 of 54 sidecars carried a TRK, about 11%.) **Originals are never stamped or OCR-rewritten.** If a stamped copy is needed for delivery it is a **new version `vN+1`**, linked to the original, with a footer `TRK · vN · date`. **CURRENT or SUPERSEDED is recorded in `00-INDEX.md`, never in the document body.**
2. **Identify the job under Rule 5:** the ID AND the address or unit in the body must agree. A folio shared by units matches the building only. A permit number matches only the job whose index lists it. Contested or ambiguous means stop.
3. **Name it by Section E** and propose its place by Section D. **Nothing is filed without approval (Rule 6).**
4. **Timing:** intake holds an item 7 days. An unresolved item becomes `OPH-open` and appears in the daily digest **on day 8**.
5. **Log it** (who, when, from, to, undo path).

**Approval is batched but honest.** The banner shows once a day: "N documents are ready to file." **Only items where ID and address agree are batched. Every exception is shown alone,** so one misfile cannot hide in a batch of 40. **The first batch is chosen from the contested numbers** (1582, 1021, 1033, 1412, 1531) **to test collisions.**

**Email circles.** My understanding, unverified: Jorge circles or marks an email (or part of one) to say "this belongs to a job and must be kept." It lands in `02-INTAKE/EMAIL-CIRCLES` with the message id, is saved as a PDF plus sidecar, matched under Rule 5, and proposed for the job's `08-CORRESPONDENCE`. **The repository has no written circling protocol.** RAMBO must find the existing one on the PC and reconcile it with this paragraph before anything is automated.

## Section G — AI compartments: read only what pertains

**Four levels; an AI stops at the first that answers its question.** L0 `README-FIRST.md`. L1 a compartment's `AGENT-INDEX.md` (what is inside, who needs it, when not to read it). L2 a job's `00-INDEX.md` or a program's catalog line. L3 the documents.

**`04-AI-SYSTEM` compartments:** `A-ACTIVE` (proof it ran in the last 30 days), `B-INACTIVE`, `C-EARLIER-VERSIONS` (`_vN`, never deleted), `D-PROOF-SCREENS`, `MAILBOX` (pointer file), `MEMORY`. Three states only: ACTIVE, INACTIVE, EARLIER-VERSION. **Programs live on the PC (`C:\AI`, `OneDrive\Scripts`, Desktop); Drive holds the catalog and source copies** so every LLM can read them.

**Read lists.** Job work: L0, the job's index, **and the index of every job under its ALIASES** (otherwise the agent on Karla never sees that `KAR-26-GROVES` holds the six newest files). **Filing work must also read `CONTESTED-IDS.md`, the TRK registry, the target job's index and `ORPHAN-REGISTER.md`. That is required, not a breach.** Program work: `04-AI-SYSTEM/AGENT-INDEX.md` and one catalog line. An AI that opens a compartment its task does not name is breaking this rule.

## Section H — Versions and status (nothing is overwritten)

1. **Version order is by `vN`, never by modified time.** Modified time is a hint and may never decide alone (a OneDrive fold-in on 2026-09-04 re-stamped documents from 2026-07-29).
2. **Status is separate:** an EXECUTED or SENT document is never replaced by a later DRAFT. **A file under 1 KB, or one that will not open, is INVALID and never current** (the Orange Tree stub on Drive is 347 bytes; the real file is 31,889).
3. **`(2)`, `- Copy` and conflict files are marked REVIEW, not SUPERSEDED,** until content is compared: the report says which is larger, which is newer, which differs.
4. Files with the same SHA-256 are listed together and counted as one.
5. **One identity per property.** The index names the survivor and lists the others under ALIASES. Merging identities is RED.
